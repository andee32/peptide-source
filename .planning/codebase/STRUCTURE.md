## Directory Purposes

**artifacts/**
- Purpose: Production-ready applications (API + UI)
- Workspace globs: `artifacts/*` in pnpm-workspace.yaml
- Built and deployed from here

**lib/**
- Purpose: Shared libraries, types, schemas
- Workspace globs: `lib/*` and `lib/integrations/*` (latter is empty)
- Never directly executed; imported by artifacts

**scripts/**
- Purpose: One-off utilities (seeding, migrations, data import)
- Workspace glob: `scripts` in pnpm-workspace.yaml
- Run via `pnpm --filter @workspace/scripts run <task>`

**.planning/codebase/**
- Purpose: GSD analysis documents (ARCHITECTURE.md, STRUCTURE.md, etc.)
- Not part of application code

## Naming Conventions

**Files:**
- Routes: `<resource>.ts` in `artifacts/api-server/src/routes/` (e.g., `products.ts`, `orders.ts`)
- Pages: `<PascalCase>Page.tsx` in `artifacts/storefront/src/pages/` (e.g., `ProductDetailPage.tsx`)
- Components: `<PascalCase>.tsx` in `artifacts/storefront/src/components/` (e.g., `Navbar.tsx`, `CartDrawer.tsx`)
- Schemas: `<resource>.ts` in `lib/db/src/schema/` (e.g., `products.ts`, `subscriptions.ts`)
- Services: `<service>.ts` in `artifacts/api-server/src/services/` (e.g., `btcpay.ts`, `email.ts`)

**Directories:**
- Resources: kebab-case or plural noun (e.g., `routes/`, `pages/`, `components/`, `contexts/`)
- Feature domains: lowercase or camelCase (e.g., `coa/` for COA visualization, `product/` for product components)

**Variables/Functions:**
- Functions: camelCase (e.g., `listProducts`, `createOrder`, `sendEmail`)
- Constants: SCREAMING_SNAKE_CASE (e.g., `CRYPTO_DISCOUNT_RATE`, `TWENTY_FOUR_HOURS`)
- React components: PascalCase (e.g., `ProductCard`, `CheckoutForm`)

**Types:**
- Table types: `<Resource>` (e.g., `Product`, `Order`, `Subscription`)
- Insert schemas: `Insert<Resource>` (e.g., `InsertProduct`, `InsertOrder`)
- Inferred types from Drizzle: Extracted via `typeof table.$inferSelect`

## Where to Add New Code

**New API Route:**
1. Define endpoint and request/response schemas in `lib/api-spec/openapi.yaml`
2. Run `pnpm --filter @workspace/api-spec run codegen` to regenerate `api-zod` and `api-client-react`
3. Create handler in `artifacts/api-server/src/routes/<resource>.ts`
4. Import generated Zod schemas from `@workspace/api-zod` for validation
5. Register router in `artifacts/api-server/src/routes/index.ts`

**New Database Table:**
1. Create schema in `lib/db/src/schema/<resource>.ts` (Drizzle pgTable, relations, insert schema)
2. Export from `lib/db/src/schema/index.ts`
3. Run `pnpm --filter @workspace/db run push` to apply migration
4. If table relates to API, update `lib/api-spec/openapi.yaml` and regenerate codegen

**New Frontend Page:**
1. Create component in `artifacts/storefront/src/pages/<PascalCase>Page.tsx`
2. Add route in `artifacts/storefront/src/App.tsx` (Wouter `<Route>`)
3. Use generated hooks from `@workspace/api-client-react` for data fetching
4. Organize sub-components in `artifacts/storefront/src/components/` (e.g., `components/product/ProductDetail.tsx`)

**New Frontend Component:**
1. Small components live in feature subdirs (e.g., `components/product/ProductCard.tsx`)
2. Layout components live in `components/layout/` (e.g., `Navbar.tsx`, `Footer.tsx`)
3. Shared UI primitives (buttons, cards) live in `components/ui/` (shadcn)
4. Import UI from `@/components/ui/*`; import utilities with `@/lib/utils` path alias

**New External Service:**
1. Create class in `artifacts/api-server/src/services/<service>.ts`
2. Singleton pattern: `export const <service> = new <Service>()`
3. Methods should be async, handle both real API and stub modes (see `btcpayService`)
4. Call from routes via named import; errors should throw and be caught by caller

**Utilities/Helpers:**
- Backend: Shared utils go in `artifacts/api-server/src/lib/` (currently empty — use or create here)
- Frontend: Utilities go in `artifacts/storefront/src/lib/` (e.g., `utils.ts`, `cn()` for classname merging)

## Special Directories

**lib/api-spec/**
- Purpose: OpenAPI contract; single source of truth
- Generated: No (manually maintained in `openapi.yaml`)
- Committed: Yes
- When to edit: Before adding/changing any API endpoint

**lib/api-zod/ and lib/api-client-react/**
- Purpose: Generated code from OpenAPI spec
- Generated: Yes (via Orval codegen in `pnpm --filter @workspace/api-spec run codegen`)
- Committed: Yes (generated artifacts are committed to ensure consistent builds without build-time codegen)
- When to edit: Never — regenerate from openapi.yaml instead

**artifacts/api-server/src/routes/**
- Purpose: REST endpoint implementations
- Pattern: One file per resource; export a `Router` instance with mounted endpoints
- Validation: Use Zod schemas from `@workspace/api-zod` for input; always `.safeParse()` then `.success` check

**artifacts/storefront/src/pages/**
- Purpose: Full-page components (mounted by Wouter in App.tsx)
- Pattern: Export named function component; can contain local state and nested sub-components
- Data: Fetch via React Query hooks from `@workspace/api-client-react`; handle `isLoading` and error states

**artifacts/storefront/src/contexts/**
- Purpose: Global React Context providers
- Pattern: Create context, define type, export `<Feature>Provider` component and `use<Feature>()` hook
- Subscribers: Typically Cart and Analytics; auth context not present yet (subscriptions use email + URL token)

**pnpm-workspace.yaml**
- Purpose: Workspace config and dependency catalog
- Critical note: `overrides:` section strips non-darwin native binaries (Replit build optimization). Keep intact when bumping versions or you risk lockfile churn.
- Catalog: All major deps are referenced via `catalog:` (e.g., `react@19.1.0`, `drizzle-orm@0.45.1`). Single source for version pinning.

**drizzle/ (in lib/db/)**
- Purpose: Auto-generated Drizzle migrations
- Generated: Yes (by `drizzle-kit push --force` or `pnpm --filter @workspace/db run push-force`)
- Committed: Yes (migrations are source of truth for schema)
- When to edit: Never — regenerate via `drizzle-kit` commands
